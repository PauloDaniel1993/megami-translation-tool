Megami Translation Process Decisions

This document records the agreed plan for organizing the Megami translation project. The previous extractor and notes remain useful evidence, but the new process should be built around structured scenes, pages, line targets, validation, and repeatable DeepSeek API calls.

Primary Goal

Build a translation workflow that is pleasant to use, resumable, technically safe, and able to preserve character tone. The first milestone is a pilot patch for s1.adx, starting with roughly the first 100 pages before scaling to the full file.

Extractor Redesign

The extractor should become a structured corpus builder, not just a Japanese-line scraper. It should decode ADX files and classify the script into scenes, pages, commands, labels, speakers, dialogue, narration, and UI text.

Unit Definition Purpose
Scene Normally starts at a useful *+ label. If a file has no such labels, create synthetic scenes. Broad context, summary, active characters, translation continuity.
Page Script content ending at @h. Textbox pacing and display constraints.
Line Original decoded script line with a stable file/line target. Exact reinsertion and validation.

Line Targeting

Every translatable line should be targeted by file, decoded line number, and source hash. Text content alone must not be used as a patch target because repeated strings are common. 

{
  "line_id": "s1:00089",
  "file": "s1.adx",
  "line_number": 89,
  "source_hash": "sha1-of-original-source-line",
  "jp": "　　やっと着きましたね、御主人様",
  "en": "",
  "role": "dialogue",
  "speaker_jp": "シュリ",
  "speaker_en": "Shuri",
  "status": "pending"
}

Textbox Rules

  • Safe maximum: 50 visible English characters per textbox line.
  • Textbox supports 4 lines total.
  • If a page has a speaker, the speaker occupies its own line.
  • Dialogue starts on the next visible line after the speaker.
  • Speaker pages therefore have at most 3 dialogue lines available.
  • Narration pages have at most 4 text lines available.
  • For the pilot, preserve the source layout instead of merging speaker and dialogue onto one line.

DeepSeek Workflow

Use direct DeepSeek API scripts rather than manual copy/paste. Keep the API translation script separate from extraction and reinsertion.

Task Recommended Model Notes
Scene/chunk summaries deepseek-v4-flash Internal and reviewable; use Pro only for confusing scenes.
Draft translation deepseek-v4-flash Medium batches, low temperature, strict JSON output.
Difficult review/final pass deepseek-v4-pro Use for character-heavy, ambiguous, lore-heavy, or sensitive scenes.

Batch Size

Use medium batches: about 15 to 25 pages per translation call, roughly 30 to 70 translatable lines, without crossing scene boundaries. Each call should include previous and next context, but only the current batch should be returned for translation. 

Prompt context:
- global translation rules
- glossary entries
- compact relevant character voice cards
- scene summary
- current chunk summary
- previous 2 pages as read-only context
- current 15-25 pages to translate
- next 1 page as read-only context
- strict JSON response schema

Scene Context Generation

DeepSeek should generate scene context in a separate pre-translation pass. Summaries should be saved as JSON and reused by translation calls. Translation calls should not invent new scene context each time. 

{
  "scene_id": "s1:scene:0001",
  "scene_title_jp": "一日目ミルフェの街",
  "scene_title_en": "Day One: Milfe",
  "scene_summary": "Celica and Shuri arrive in Milfe after a difficult journey. Celica notices a fatigue-induced change in his body and hides it from Shuri while deciding to find lodging.",
  "timeline": [
    "Celica arrives in Milfe and observes the city.",
    "He notices a physical change caused by fatigue.",
    "Shuri joins him and asks what is wrong.",
    "Celica deflects and decides to find an inn."
  ],
  "active_characters": ["Celica", "Shuri"],
  "tone_notes": [
    "Celica's narration is dry and self-contained.",
    "Shuri is polite and concerned."
  ],
  "status": "draft"
}

Validation Before Patching

  • All expected line_id values are present.
  • No duplicate or unknown line_id values appear.
  • Source hashes match the current decoded source.
  • English text is strict CP932 encodable.
  • Line length stays within 50 visible characters.
  • Speaker pages stay within 3 dialogue lines.
  • Narration pages stay within 4 text lines.
  • Speaker names match the glossary.
  • No Japanese remains in English fields unless explicitly allowed.

Glossary And Style

The glossary is authoritative for character names, place names, menu terms, address terms, spells, items, and recurring terminology. DeepSeek should not invent romanizations.

The large character profile document should be condensed into compact character voice cards. Translation calls should include only the relevant cards for the current batch.

Separate Queues

Do not mix every text type into one translation queue. Use separate handling for:

  • Story dialogue and narration.
  • Menu/UI commands such as @cmf.
  • Location/title commands such as @maptitl.
  • System text.
  • Bonus or staff-room content.
  • Script labels, which should remain unchanged unless proven visible.
